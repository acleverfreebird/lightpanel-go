# LightPanel MVP implementation plan

Goal: finish the existing panel as a small Linux-only single executable.

Architecture: Go 1.25+, net/http, embedded HTML/CSS/native JS, bcrypt, bounded in-memory sessions, TOML. No database, shell interpolation or optional terminal. Linux /proc metrics and systemd/firewall CLI adapters.

- [x] Configuration/auth: strict TOML + LP_* overrides, no default password, localhost default, TLS, session revocation, bounded login rate limits, CSRF and JSON audit. Test missing credentials, login/logout, CSRF and expiry.
- [x] Files: os.Root confinement, bounded directory pages, streaming exclusive uploads/downloads, nonrecursive deletion and descriptor-based chmod. Test traversal, escaping symlinks, hardlinks, FIFO, root deletion, upload size.
- [x] Linux operations: cached metrics, searchable processes with identity-checked pidfd signals, systemctl/journalctl with bounded output/timeouts and fixed executable paths, explicit firewall rule semantics. Test parsers, argument validation, command failures.
- [x] Embedded UI: login, overview, process search, service actions, file browser/upload/download/chmod/delete, log viewer and firewall. Safe DOM text, no CDN or inline scripts. Integration-test all routes and assets.
- [x] Delivery: run Linux tests and race detector, vet, amd64/arm64 static builds; smoke-test login and file operations in WSL; document architecture/API/deployment/resource estimates/extensions in that order.

Existing source is not a Git repository; no commits or worktrees are created. Implement in the current session. Never exercise destructive management operations against the host; tests use temporary files, owned child processes, and injected command runners.
