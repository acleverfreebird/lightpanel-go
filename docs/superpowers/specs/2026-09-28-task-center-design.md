# 任务中心 UI 调整（已确认）

## 目标与设计

任务中心入口放在侧边栏导航的最后一项（防火墙之后），显示执行中数量；移除右下角悬浮入口。点击仍打开 dialog，不切换当前页面。入口在没有任务或接口暂时失败时也可用。

推荐采用左右分栏弹窗：左侧任务列表，右侧执行详情与日志。相比原有上下堆叠，更方便同时浏览任务与输出；相比独立页面，保留用户要求的弹窗交互。窄屏改为上下排列。

复用 app.css 的暖灰底色、白色表面、橙色强调色、绿色成功状态、红色失败状态、圆角和字体变量，不照搬宝塔配色。

## 内容与交互

- 顶部显示任务中心标题、执行中数量、清除已结束任务与关闭按钮。
- 列表显示名称、执行中/已完成/失败状态和创建时间；选中态清晰，整行可点击并支持键盘。
- 默认选中执行中的任务，否则选中最近任务。
- 详情显示任务标题、状态、开始与更新时间、错误原因及等宽日志区域。
- 日志提供复制和跟随最新输出；用户向上阅读时不强制滚动。
- 无任务、等待输出、加载中和读取失败均有明确反馈；接口失败不误报任务执行失败。
- 弹窗关闭后后台任务继续执行，保留现有完成事件与应用/站点刷新行为。

## 数据与可靠性

复用 /api/tasks 和 /api/tasks/{id}，保持现有两秒轮询。任务从执行中转为结束时必须补取最终详情，防止状态和末尾日志停留在旧版本。快速切换任务时丢弃过期请求结果，避免日志串台。清理任务后同步刷新选择和空态。

当前日志采集存在后端边界：直接执行模式按步骤追加输出，helper 模式在操作结束后返回输出。本次界面准确显示服务器已有日志，并在尚无输出时提示等待，不将其描述为逐行实时流。逐行流式输出需要另行扩展命令执行及 helper 协议。

## 验证

验证执行中到成功/失败的最终日志刷新、快速切换的请求竞态、清理后的选择与空态、只读模式、复制、滚动跟随、桌面与窄屏布局。运行相关测试和 Go 项目测试；同步替换指向右下角入口的旧文案。
